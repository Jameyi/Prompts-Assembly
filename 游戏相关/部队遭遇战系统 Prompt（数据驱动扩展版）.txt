你是一名资深游戏战斗系统架构师，请设计一个高度模块化、数据驱动的幻想SRPG部队遭遇战系统。

目标：

实现类似经典日式幻想SRPG中的：
“战略地图上的两支部队接触后，进入独立战斗场景，双方军团持续交战”。

但该系统必须设计为一个通用战斗框架。

核心原则：

【战斗系统负责执行规则】
【所有战斗规则由外部数据驱动】

禁止：

- 将技能类型写死
- 将兵种逻辑写死
- 将地形效果写死
- 将Buff效果写死
- 将状态效果写死

所有扩展内容必须通过接口或者配置数据传入。


================================
一、整体战斗流程
================================


战斗生命周期：

BattleStart

↓

LoadBattleData

↓

InitializeArmy

↓

ApplyInitialEffects

↓

ChargePhase

↓

EngagementPhase

↓

CombatLoop

↓

BattleEnd


战斗模块接收：

BattleContext


包括：


双方部队数据

战斗场景数据

地形数据

初始Buff数据

指挥官数据

技能数据

战斗时间


例如：

BattleContext

{

playerArmy,

enemyArmy,

terrainData,

initialEffects,

commanderData,

skillList,

battleDuration

}


================================
二、部队结构设计
================================


部队：

Army


包含：

Commander

+

SoldierUnits



--------------------------------

Commander：

可以是：

英雄

或者

普通NPC队长


属性：

id

name

level

hp

attack

defense

leadership

morale

passiveSkills

activeSkills



注意：

Commander自身不负责技能逻辑。

技能全部通过Skill系统加载。


--------------------------------

SoldierUnit：

独立作战单位。


数据来自外部配置：

SoldierConfig


例如：


{

id,

name,

maxHp,

attack,

defense,

morale,

attackSpeed,

animationSet,

attributeData

}



禁止：

if(type=="骑兵")

if(type=="步兵")


战斗系统不能判断兵种名称。


================================
三、技能系统设计
================================


设计通用Skill接口。


技能数据由外部传入。


SkillData：


{

skillId,

skillName,

skillType,

triggerType,

targetType,

effectList,

duration,

cooldown,

condition

}



技能类型：

不要使用硬编码枚举限制。

支持扩展：

Passive

Active


例如：

被动技能：

- 战斗开始触发
- 条件满足触发
- 血量低于某比例触发
- 友军死亡触发
- 时间节点触发



主动技能：

由玩家在战斗过程中点击释放。


60秒/90秒战斗时间内：

玩家可以打开技能界面。

选择技能。

发送：

UseSkill(skillId,target)


进入技能执行流程。


================================
四、技能效果系统
================================


技能本身不直接修改单位。


技能产生：

Effect


设计：

EffectProcessor


例如：

DamageEffect

HealEffect

BuffEffect

DebuffEffect

ModifyAttributeEffect

ModifyMoraleEffect

ModifyTerrainEffect

SummonEffect



技能：

只负责：

产生Effect列表。


Effect系统负责：

执行效果。


例如：

火焰冲击技能：

SkillData:

产生：

DamageEffect


鼓舞技能：

产生：

AttackBuff

MoraleBuff


诅咒：

产生：

AttackDebuff

DefenseDebuff



未来增加新效果：

不修改战斗核心代码。


================================
五、Buff / Debuff状态系统
================================


设计：

StatusEffect系统。


所有状态统一处理。


例如：

Buff：

攻击增加20%

防御增加10%

士气提高


Debuff：

攻击降低

移动降低

持续伤害


数据结构：


StatusData

{

statusId,

attributeModifier,

duration,

stackRule,

source

}



支持：

战斗开始前已有Buff。

例如：

部队进入战斗之前：

已经受到：

装备效果

地图事件

剧情效果

技能效果


这些状态通过：

initialEffects


传入。


战斗开始：

自动加载。


================================
六、地形影响系统
================================


设计：

TerrainModifier接口。


战斗开始时：

传入：

TerrainData


例如：

{

terrainId,

name,

modifierList

}



modifierList:


{

attribute,

value,

targetCondition

}


例如：


森林：

某些单位：

攻击+20%

防御+10%


沼泽：

攻击-15%

速度-20%



注意：

战斗系统不知道：

什么是森林。

什么是沼泽。


只读取Modifier。

================================
